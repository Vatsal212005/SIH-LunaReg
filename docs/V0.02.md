# LunaReg V0.02 - Low-Compute Learned Matching Benchmark

V0.02 does **not train any model**. It benchmarks pretrained learned matchers on the
already-verified V0.01.2 OHRC to LRO canonical pair.

## Why V0.02 exists

V0.01.2 established a valid common 1 m map grid and showed that the unchanged
SIFT/RANSAC baseline retained only five geometric inliers on the real pair. V0.02 asks
whether generic learned matchers solve the same correspondence problem before any
LunaReg-specific model is designed.

## Default eco profile

- canonical scientific pair remains untouched at 1500 x 1500 and 1 m/px
- benchmark working copy: 640 x 640
- SuperPoint keypoint cap: 768
- LightGlue adaptive early stopping enabled
- LightGlue mixed precision enabled on CUDA
- LoFTR mixed precision attempted first on CUDA
- LoFTR does **not** automatically retry in FP32 if FP16 fails
- batch size: one image pair
- no training
- no warm-up benchmark loops
- one inference per matcher
- no `torch.compile`
- only one learned matcher is resident in VRAM at a time

A 640 px working-grid pixel represents about 2.34375 m for the frozen 1500 px,
1 m/px canonical crop. `ground_equivalent_rmse_m` is therefore only a scaled
working-grid residual, not an independent absolute lunar-registration truth metric.

## Thermal policy

Before each learned matcher, V0.02 checks `nvidia-smi`.

- below 78 C: proceed
- 78 C or above: wait
- resume at 74 C or below
- 84 C or above before a model starts: refuse to begin that model
- maximum cooling wait: 5 minutes

This is an additional conservative software guard. The laptop's own firmware thermal
protection remains authoritative.

## Install

From the project root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\INSTALL-V0.02.ps1
```

The installer reuses the existing backend virtual environment where possible. If CUDA
PyTorch is missing, it installs the Windows CUDA 12.8 PyTorch wheels. Model weights are
prefetched on CPU so the first GPU run does not mix network downloads with inference.

## Run

Lowest-compute full benchmark:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\RUN-V0.02.ps1
```

Run only LightGlue first:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\RUN-V0.02.ps1 -Model lightglue
```

Run only LoFTR:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\RUN-V0.02.ps1 -Model loftr
```

Balanced mode is available later if eco mode is inconclusive:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\RUN-V0.02.ps1 -Mode balanced
```

Do not use balanced mode until the eco results have been inspected.

## Outputs

Default eco outputs:

```text
backend/data/processed/v002_benchmark_pair_001_eco/
```

The directory contains:

- `source_640.png`
- `reference_640.png`
- `working_pair.json`
- `sift/result.json`
- `lightglue/result.json`
- `loftr/result.json`
- per-model `matches_all.jpg`
- per-model `matches_inliers.jpg` when a homography exists
- per-model `overlay.jpg` when a homography exists
- `benchmark_summary.json`
- `benchmark.csv`

## V0.02 acceptance criterion

V0.02 is complete when the eco profile has produced interpretable results for
SuperPoint + LightGlue and LoFTR, or a reproducible model/runtime failure has been
identified. XoFTR, RoMa, training, lunar-specific adapters, and full-resolution learned
matching are intentionally outside V0.02.
